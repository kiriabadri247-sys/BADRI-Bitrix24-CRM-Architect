# BADRI Bitrix24 CRM Architect

Рабочий проект для анализа, проектирования, документирования и безопасного сопровождения решений Bitrix24. Репозиторий предназначен для хранения общих материалов, шаблонов, тестовых сценариев и вспомогательных инструментов. Правила работы определены в `AGENTS.md`.

## Структура каталогов

- `clients/` — локальные материалы по клиентам; содержимое не должно попадать в Git.
- `docs/` — проектная, архитектурная и пользовательская документация без персональных данных.
- `knowledge/` — база знаний по CRM, REST API, вебхукам, бизнес-процессам, смарт-процессам, телефонии, интеграциям и аналитике.
- `scripts/` — вспомогательные скрипты; перед применением к рабочему порталу обязательны проверка, dry-run и тестовая выборка.
- `templates/` — обезличенные шаблоны документов, настроек и рабочих материалов.
- `tests/` — тест-кейсы, тестовые данные без персональных данных и результаты локальных проверок.
- `exports/` — локальные выгрузки из внешних систем; содержимое исключено из Git.
- `diagrams/` — архитектурные схемы, карты процессов и интеграций.
- `archive/` — локальные архивы и резервные версии; содержимое исключено из Git.

## Хранение клиентских данных

- Персональные, коммерчески чувствительные и идентифицирующие данные хранятся только в разрешённых защищённых системах.
- Каталоги `clients/`, `exports/` и `archive/` считаются локальными и исключены из Git полностью.
- В документацию, тесты, шаблоны и примеры допускаются только обезличенные или синтетические данные.
- Перед публикацией или передачей материалов необходимо проверить их на телефоны, email, ФИО, реквизиты, идентификаторы CRM, содержимое сделок и другие чувствительные сведения.
- Рабочие выгрузки нельзя переименовывать или переносить в отслеживаемые каталоги для обхода правил `.gitignore`.

## Секреты

- Пароли, токены, вебхуки, API-ключи и другие секреты запрещено хранить в коде, документации и Git.
- Локальные секреты должны передаваться через переменные окружения или файлы `.env`, которые исключены из Git.
- Примеры конфигурации не должны содержать действующие значения. Если потребуется `.env.example`, его добавляют отдельно только с безопасными заглушками и соответствующим исключением из `.gitignore`.
- Секреты и персональные данные нельзя выводить в логи, тестовые отчёты и сообщения об ошибках.

## Работа с Git

- Перед изменениями необходимо проверять `git status` и сохранять несвязанные пользовательские изменения.
- Изменения должны быть минимальными, тематически связанными и проверяемыми.
- Нельзя выполнять `git reset --hard`, `git clean -fd`, force push, удаление веток или переписывание истории без явного согласования.
- Коммиты создаются только по явному запросу пользователя; секреты, клиентские данные, рабочие экспорты и резервные копии в них не включаются.
- Для крупных задач рекомендуется отдельная ветка с префиксом `codex/`.
- Перед добавлением файлов следует проверить `git diff`, `git status` и результат применения `.gitignore`.
