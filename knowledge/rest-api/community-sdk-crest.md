# CRest — внешний PHP SDK для Bitrix24 REST API

**Репозиторий:** https://github.com/bitrix-tools/crest  
**Владелец:** `bitrix-tools` (отдельная GitHub-организация; не путать с `bitrix24`)  
**Основной язык:** PHP  
**Лицензия:** MIT  
**Ветка источника:** `master`  
**Проверено:** 2026-10-30  
**Роль в базе знаний:** внешний справочный ресурс и образец реализации, не обязательная зависимость.

## Назначение

Небольшой PHP SDK `@bitrix/crest` для вызова REST API Bitrix24:

- входящие вебхуки;
- локальные приложения;
- тиражные приложения с OAuth 2.0;
- примеры вызовов REST через класс `CRest`;
- требования к PHP cURL, HTTPS/SSL и проверке сервера (`checkserver.php`).

README содержит инструкции на русском и английском.

## Правила применения в проектах

1. **Сначала no-code:** CRM, роботы, триггеры, бизнес-процессы и стандартные интеграции. SDK рассматривать только при подтверждённой необходимости REST/PHP.
2. Не считать примеры CRest актуальным контрактом API: методы, scope, ограничения и параметры проверять по официальной REST-документации и на конкретном портале.
3. Перед использованием изучать исходники, обработку ошибок, OAuth refresh и безопасное хранение токенов. В README прямо предупреждается, что реализацию файлового хранения токенов необходимо переопределять для тиражных multi-tenant-приложений.
4. Не включать реальные вебхуки, `client_secret`, токены, клиентские данные или логи с персональными данными в Git. Использовать конфигурацию вне репозитория и секреты окружения.
5. Не копировать исходники CRest в нашу базу знаний автоматически. Если библиотека потребуется в рабочем PHP-проекте, фиксировать версию/commit, лицензию, изменения и план обновления.
6. Для Python, JavaScript или решений без PHP CRest не является необходимой библиотекой.
7. Не запускать исходные примеры на клиентских порталах: README содержит *изменяющий* пример `crm.lead.add`, поэтому сначала проверять код на тестовом окружении.
8. Учитывать, что последняя опубликованная активность репозитория может отставать от новых версий REST API; проверять совместимость перед внедрением.
