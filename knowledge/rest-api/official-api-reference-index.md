# Официальный справочник REST API Bitrix24 — индекс и порядок работы

**Источник:** https://apidocs.bitrix24.ru/api-reference/index.html  
**Тип:** официальная документация разработчика Bitrix24; внешний онлайн-источник, без копирования текстов API.  
**Проверено:** 2026-10-30  
**Приоритет:** основной источник для проверки поддерживаемых REST-методов, параметров, скоупов и ответа.  
**Статус:** REFERENCE ONLY / NO LIVE INTEGRATION.

## Структура справочника

Главная индексная страница разделяет методы и платформенные возможности по следующим группам:

1. **Основы REST API** — типы данных, форматы параметров, скоупы, общие методы, события, REST 3.0, устаревшие методы.
2. **Продажи и клиенты** — CRM (лиды, сделки, контакты, компании, смарт-процессы), интернет-магазин, торговый каталог, платежные системы, генератор документов, подпись.
3. **Автоматизация и работа компании** — бизнес-процессы и роботы, задачи, группы, календарь, журнал событий, структура компании, пользователи и учет рабочего времени.
4. **Коммуникации** — чаты, боты, открытые линии, телефония, SMS-провайдеры, почта.
5. **Данные и контент** — Диск, файлы, хранилище приложения, списки, сайты, база знаний, онлайн-запись и другие инструменты.
6. **Платформа** — встраиваемые виджеты, BI-коннектор, BitrixGPT и Вайб.

Справочник дополнительно ссылается на разделы **лимитов REST API**, **кодов ошибок** и официальный **MCP-сервер документации**. Эти разделы необходимо читать непосредственно при проектировании конкретного решения.

## Как применять в проектах BADRI

1. Сначала описать бизнес-операцию, данные, права, тариф и облачную/коробочную версию.
2. Проверить штатный no-code вариант и использовать REST лишь при обоснованной необходимости.
3. Найти профильный раздел API и **конкретную страницу метода**; индекс не является контрактом метода.
4. Сверить назначение метода, его актуальность/deprecation, HTTP-запрос, обязательные параметры и форматы, результат, ошибки, скоупы, ограничения, версию REST.
5. Помимо скоупов проверить фактические права пользователя: скоуп не обходит ACL портала.
6. Сопоставить выбранный метод с целевой CRM-сущностью и фактическими кодами полей, не выдумывать методы и статусы.
7. Предусмотреть лимиты, пагинацию, retry/backoff, идемпотентность, журналирование без секретов, резервную выгрузку, dry-run и тестирование перед записями.
8. При изменениях документации перепроверять ссылки и фиксировать дату/версию. REST 3.0 и legacy REST не смешивать без проверки совместимости.
9. Примеры SDK (в том числе [CRest](community-sdk-crest.md)) — вспомогательный материал; официальный справочник приоритетнее.
